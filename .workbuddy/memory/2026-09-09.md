## Transfer Engine 修复（8055599，test）— 主人 issue: 买不起的 Haaland

**根因（一行）**：`context.build_state` 把 FPL API `entry_history.bank`（0.1M 整数，`20`=£2.0m）原样写入 `state.bank`，而 `player.price` 已 `now_cost/10` 是百万浮点 → `bank + out.price ≥ in.price` 变成 `20 + 6.0 ≥ 15.5` 误判买得起 Haaland。`state.bank` 单位与球员 price 不同。

**Phase 1 预算校验**（必做，已完成）：
- `brain/context.py:build_state` 把 bank `/10` 归一到百万浮点（与 price 同单位），注释写明 `20`⇒`£2.0m`。
- `brain/data_store.py:validate_state` 加 bank 单位 sanity（`0 ≤ bank ≤ 300`，>£300m 报错防 0.1M 漏除回归）。
- `brain/transfer.py:evaluate_transfers` 重写为 **Transfer Package Search**：候选 (out,in) 对上 DFS 枚举合法包，字典序最大化 `(covered_forced, total_gain)`；内置包级预算校验 `Σin ≤ bank + Σout`（FPL 先卖后买真实可执行）；同队 ≤3、in 互斥、同位置结构；强制出售（伤病/状态）优先覆盖。
- 新增 `transfer.summarize_package(bank, suggestions)` 给前端/history 用。

**Phase 2 升级**（推荐，已合入 Phase 1）：从「逐个球员推荐」改为「完整转会包搜索」。端到端 84 项 unittest 全绿。

**输出落地**：
- `state.decision.transfer_package = {gain, out_count, total_out_price, total_in_price, budget_before, transfer_cost, budget_after, feasible, score_base}`。
- `history.json` 每条 entry 顶层平铺 `budget_before / transfer_cost / budget_after`（用户要的复盘字段）；旧数据缺字段 → 前端容错。
- 前端 `fmtBank` 不再 `/10`（state.bank 已是 £m）；本周动态 + 历史转选择区追加「净花费 / 转会前后 Bank」摘要行；`web/style.css` 加 `.xfer-summary` 样式。
