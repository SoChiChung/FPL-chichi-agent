## 1. 产品定位与设计原则

### 1.1 一句话定位

> **这里不是一个看数据的后台，而是一个"会自己玩 FPL 的 AI"的公开养成日记。**

访客带着的问题不是「算法权重是多少」，而是：
**它这周做了什么 → 做得怎么样 → 为什么这么做 → 它变聪明了吗。**

### 1.2 三条叙事线（信息架构的组织逻辑）

| 叙事线 | 回答 | 落点 |
|---|---|---|
| **身份线**（它 *是* 谁） | 名字 / 风格 / 风险偏好 / 赛季 | Sidebar A·B·D + Header |
| **周历线**（它 *这周* 做了什么） | 动态 → 成绩 → 阵容证据 → 思考 | Main ① → ④ |
| **成长线**（它 *一路* 表现如何） | 逐轮决策档案 → 三条趋势 | Main ⑤ → ⑥ |

### 1.3 设计原则

1. **行动先于指标**：本周动态永远在内容区最顶部；数字是故事的注脚，不是主角。
2. **单一口径，不说谎**：严格区分「AI 的决策与建议」vs「FPL 官方实际快照」（§6.1），所有展示口径一致、可追溯。
3. **时间可追溯**：每个决策带 `决策时间`，每份数据带 `数据时点`，两者标签语义分开（§6.5）。
4. **快读优先**：首屏 10 秒内回答前三个问题；正文日志 ≤3 段、50–120 字；次要信息折叠。
5. **游戏化人格，不做儿童界面**：视觉 Phase 3 用"亲和力 + 轻松感"表达人格（动森气质，非动森 UI）。

### 2.2 信息分层模型

| 层 | 职责 | 模块 | 信息深度 |
|---|---|---|---|
| **身份层** | 第一眼回答"它是谁、可信不可信" | Header、Sidebar A/B/D | 常驻可见（Sidebar sticky） |
| **快读层** | 回答"这周做了什么、成绩如何" | Main ①、② | 首屏内、秒读 |
| **证据层** | 回答"动作用于阵容上长什么样"（转会前 vs 转会后） | Main ③ | 切换式，可视对比 |
| **理解层** | 回答"为什么这么做"（完整留档） | Main ④ | ≤3 段，次要信息折叠 |
| **回溯层** | 回答"历史如何、是否变聪明" | Main ⑤、⑥ | 按需展开（Accordion / Tab） |

> 优先级依据简报：「本周做了什么(1) > 成绩(2) > 为什么(3) > 阵容(4) > 历史(5) > 数据细节(6)」。
> 主人拍板：阵容(证据层) 位于完整思考日志(理解层) 之前——设计理由见 §3.3 ③/④ 说明。

### 2.3 横向状态轴（贯穿全页的 GW 状态）

IA 中的每条内容都挂在**一个 GW**上，全页统一用「GW 三态」表达（详见 §4.4 / §7.1）：

```
每轮 GW 状态机：   未开始 ──deadline──▶ 进行中 ──FPL 结算──▶ 已结算
                    （gw > 当前GW）    （= 当前GW）       （history[i].points 已回填）
```

- 数字旁永远带状态上下文，杜绝"白看一排无主数字"。

## 3. 【交付物 2】页面模块说明（含内容设计）

### 3.0 内容总则

**语气（Content Tone）**：友善、具体的"玩家叙事"，不用数据后台腔。示例对照：

| 数据后台腔（避免） | 玩家叙事腔（采用） |
|---|---|
| GW4 决策记录 | 这周它决定这样踢 |
| Transfer OUT 565 / IN 367 | 卖掉 M.Sangaré，买入 Gakpo（同位置 Market Score +14.7 的差距，它认为值得） |
| Overall Rank: 10,331,456 | 赛季总排名 10.33M（数据口径 = 赛季累计） |
| 待结算 | 这轮成绩还没结算，等 FPL 出分自动更新 |

**真实口径（Truthfulness）**：AI **不代主人提交** FPL 操作（或由主人手动执行）。因此——
- 涉及转会的措辞一律区分「**AI 建议** / **AI 决策**」；凡指官方实际阵容处使用「当前阵容（FPL 实际）」。
- 展示的是"AI 的思考与建议"这一事实本身就有价值，不需要伪装成已执行。

**字数纪律（沿用 v1.1 §5）**：日志 ≤3 段、每段 50–120 字、10 秒读完；Sidebar 摘要另定（见 §3.2-C）。

### 3.1 Sidebar（25% · 身份层）

#### A. AI Manager Profile
| 元素 | 内容 | 优先级 |
|---|---|---|
| 头像 + AI 经理名 | 🧅 头像 + 人格名（待定，§10） | 最高 |
| Strategy Style | 由 `strategy_snapshot.strategy` 映射（如 `market_consensus` → 市场共识型） | 高 |
| Risk Level | 由 `allow_hits / max_free_transfers` 映射（Low/Medium/High，映射表见 §6.3） | 高 |
| Season / Current GW | `2026/27 · GW4`（GW 徽章式强调） | 高 |

设计要点：这 4 行是"它是谁"的最小回答；字段缺失显示 `-`，不阻塞。

#### B. 当前战绩
| 展示 | 数据源 | 语义 |
|---|---|---|
| Total Points | `state.points` | 赛季累计总分（label 写「总积分」，避免与单轮混淆） |
| Overall Rank | `state.rank` | 赛季累计总排名（`10.33M` 格式） |
| Gameweek Rank | 最近已结算 `history[i].rank` | 语义 = 最近一个**已结算**单轮的排名；无已结算轮显示「暂无已结算轮次」 |

设计要点：三行纯数字+小标签；点击 GW Rank 行可锚点至 ⑥ 趋势。

#### C. 最近一次思考
- 取**最近一次决策日志**（与 Main ④ 同轮时为同一内容），按压缩规则截为 **≤60 字**摘要 + 决策时间小字。
- 摘要与 Main ④ 的完整内容构成"teaser → 全文"关系，点击「查看完整思考 ↓」锚点滚动到 ④。
- （简报要求 Sidebar 摘要 50–120 字：默认采用 ≤60 字 teaser 以避免与 ④ 全文整段重复；若主人坚持 50–120 整段，接受重复即可，见 §10。）

#### D. 关于我（External Links 预留区）
信息层级（权重从大到小，视觉 Phase 3 落实）：
1. **品牌名 + 用户名**（最大）——`name` + `handle`
2. **核心数据行**（次大）——`heroMetrics` 白名单从 state 实时取（默认 `rank / points`）
3. **tagline**（辅助文字）
4. **平台导航**（最弱）——图标缩小降对比，仅作识别与跳转辅助

内容由 `web/config.js` 驱动，空平台列表时仅隐藏导航行，品牌卡保留。
> ⚠️ 现配置 tagline = `FPL Analytics · Data Tracking` 与「养成日志」叙事冲突（见 §7.4），待主人换文案。

### 3.2 Main（75%）模块说明

#### ① AI 本周动态 —— 内容区最顶部（快读层首屏）
| 内容 | 说明 |
|---|---|
| GW 标题 | 「GW4」徽章 + 轮次状态标签（进行中/已结算） |
| 阵型 | AI 决策阵型 `352` → 展示 `3-5-2`（口径 = AI 决策，§6.1） |
| 队长 / 副队长 | 名字 + `C` / `V` 徽章 |
| 转会 | 每笔 `OUT 球员名 → IN 球员名` + 原因（`reason`）一行；**无转会**显示「本轮未进行转会：市场共识未明显转向，全员健康」类短语 |
| 内嵌"为什么" | 转会/队长行的原因就地呈现（快读层即满足问题 3 的第一层） |
| 截止提醒 | 若有 `next_deadline`：小字「本轮截止 9/12 12:30 (GMT+8)」 |
| CTA | 有建议转会时提供按钮「查看转会后阵容 →」：滚动至 ③ 并自动切到「转会后」视图 |

#### ② 本轮成绩（快读层）
| 展示 | 数据源 | 空态 |
|---|---|---|
| GW Points | `history[当前gw].points`（已结算）| 进行中 →「待结算」（进行中徽章） |
| GW Rank | `history[当前gw].rank` | 进行中 →「待结算排名」 |
| Overall Rank | `state.rank`（赛季累计，label 注明） | `-` |
| 银行（备注小行） | `state.bank` → `/10` → `£2.0m` | `-` |

设计要点：与 Sidebar B 数据同源但**语境不同**（这里是"这轮结账"，Sidebar 是"赛季账面"），文案必须分开，避免两处数字含义打架。

#### ③ 阵容对比（证据层）★ 已知问题 2 的对策载体
双视图：**当前阵容（FPL 实际）** / **转会后阵容（AI 建议）**。
| 元素 | 设计 |
|---|---|
| 切换控件 | Segmented（两按钮），URL 支持 `?view=cur\|sug` 直达 |
| 当前视图 | 官方实际 15 人（`state.team`），含 C/V、阵型说明 |
| 转会后视图 | `state.suggested_squad`（后端已落：完整 15 人 + breakdown） |
| 差异提示 | 视图头一行：`按 AI 建议：转出 M.Sangaré → 转入 Gakpo（1 笔）`；转入球员卡带「新入」角标，转出球员在当前视图带「拟转出」角标 |
| 无建议转会 | 切换器隐藏、仅当前视图；标题旁注明「本轮无转会建议」 |
| 空态 | 未建队（首轮前）显示「AI 正在建立第一套阵容……」 |

设计要点：证据层紧贴动作层（①），让"它说了要换谁"和"换了之后长什么样"在同一次滚动内闭环；**不做**两视图并排分屏（移动端不可用），用切换+角标承担 diff 职责。

#### ④ AI 思考日志（理解层）
| 元素 | 规则 |
|---|---|
| 标题行 | 「GW4 · 思考日志」+ **决策时间**小字（`fmtTime(decided_at)`，本地时区；缺失显示 `-`） |
| 正文 | notes 聚合：优先级 转会>队长>无转会>阵容>其他；≤3 段；每段 50–120 字（截断加…） |
| 叙事排序 | 转会操作 → 队长选择 → 排兵/额度（非原始顺序） |
| 折叠 | `external_source / data_missing / warning` 类收进「更多细节」`<details>` |
| 角色 | 这是"为什么"的**完整留档**；首层原因已在 ① 内嵌，此处读深 |

> ③/④ 顺序说明（主人拍板：阵容在前）：① 已内嵌即时"为什么"，④ 是完整档案，因此将**行动的证据（③）**置于**完整档案（④）**之前，保证"宣布转会 → 立即看新阵容"的邻接叙事；两模块顺序互换成本极低，若后续观察数据支持"先解释再证据"可一键对调（见 §10）。

#### ⑤ 历史记录（回溯层 · Accordion）
- 折叠条：`GW3 · 37 分 · GW Rank 9.50M · OR 10.33M`（未结算显示字段感知空态）；默认展开最近一轮，其余收起。
- 展开后四区：
  1. **Result**：GW Points / GW Rank / Overall Rank（已结算值；未结算=进行中）
  2. **Transfers**：实际（已落）转会记录 out→in + reason；无则「本轮未进行转会」
  3. **Captain / 阵型**：当时的 C/V 与阵型选择
  4. **Thought + Decision Time**：当时决策日志（≤3 段）+ `decided_at`
- 语义：**每条历史 = 一次 AI 决策**（GW1 无决策不显示）。

#### ⑥ 趋势曲线（回溯层 · 数据细节）
- 单容器 + 三 Tab：`Overall Rank` / `GW Points` / `GW Rank`（简报三个维度全满足）。
- 排名类 Y 轴反向（小在上）+ `k/M` 压缩；积分正向；null 轮不画点；仅 1 点时画圆点+数值。
- 图注小字说明口径：`Overall Rank 与 GW Points 来自已结算轮次回填`。

## 4. 【交付物 3】用户浏览路径（UX Flow）

### 4.1 三类访客路径

**A. 新访客（第一次打开 · "这是谁"）**
```
Header 名字/赛季 ─▶ Sidebar A Profile（风格·风险） ─▶ ① 本周动态（它在玩 FPL！）
   ─▶ ③ 阵容对比（真的有一个队） ─▶ ⑤/⑥（往下滑看到它在成长） ─▶ D 关于我（关注入口）
```
首屏 10 秒内须可回答前 3 问；"为什么"由 ① 内嵌原因兜底，深读靠 ④。

**B. 每周回流（核心用户 · "这周怎么样"）**
```
① 本周动态（转会？队长？） ─▶ ② 成绩（结算没？） ─▶ [CTA] ③ 转会后阵容
   ─▶ ④ 思考日志（为什么） ─▶ ⑤ 与上周对比（它吸取教训了吗）
```

**C. 考古者（"它变聪明了吗"）**
```
⑥ 趋势 Tab（OR 曲线向上？） ─▶ ⑤ 展开关键 GW（当时怎么想 vs 后来结果）
   ─▶ ③ 那一轮的阵容证据
```

### 4.2 关键交互与跨模块联动

| # | 交互 | 行为 | 落点 |
|---|---|---|---|
| 1 | Sidebar C「查看完整思考」 | 平滑滚动至 ④ | A-C / ①-④ |
| 2 | ① 转会行「查看转会后阵容」 | 滚动至 ③ + 自动切 `sug` 视图 | ①→③ |
| 3 | ③ Segmented 切换 | 切数据源渲染，`?view=` 可直达/可分享 | ③ |
| 4 | ⑥ Tab 切换 | 换数据集与 Y 轴方向 | ⑥ |
| 5 | ⑤ Accordion | 原生 `<details>`；默认开最近轮 | ⑤ |
| 6 | Sidebar B GW Rank | 锚点至 ⑥ 并选对应 Tab | B→⑥ |
| 7 | 刷新语义 | 页面无手动刷新按钮：静态站随 Actions 30 分钟自动出新快照；Header/Footer 展示 `last_update`，用户自行判断新鲜度 | 全局 |

### 4.3 状态与空态设计（UX 兜底）

| 场景 | 文案/行为 |
|---|---|
| 数据加载中 | 「正在读取最新 FPL 数据……」占位骨架 |
| 快照过期/新旧交替期 | 不猜、不遮：Header 时间戳如实显示；GW 标签如实显示三态 |
| 历史未结算 | 积分空 =「待结算」；排名空 =「待结算排名」（字段感知，沿用 BugFix v1.0） |
| 无历史（赛季首轮前） | 「AI 的赛季还没开始——第一轮截止后，这里会有它第一个决定」 |
| 无建议转会 | ③ 隐藏切换器 + 「本轮无转会建议」；① 无转会行 |
| `decided_at` 缺失 | 显示 `-`（早于时间记录功能落地的轮次） |
| 平台外链为空 | 仅隐藏导航行，品牌卡保留 |
| 禁用动效偏好 | `prefers-reduced-motion` 时停用滚动/展开动画 |

## 5. 【交付物 4】Dashboard 布局草图（Wireframe）

### 5.1 桌面（> 768px · 1140px 内容容器居中）


## 6. 【交付物 5】数据字段映射关系

### 6.1 口径总则（最重要的一张表）

| 来源域 | 内容 | 语义 | 前端用途 | 示例（快照实值） |
|---|---|---|---|---|
| `decision.*` | AI **决策产物**：formation / captain / vice / starting_xi / bench / recommended_transfers / transfer_package | 它"决定/建议"做什么 | ① 本周动态、③ 转会后视图底座、④ 日志 | `decision.formation=352`；建议转会 M.Sangaré→Gakpo |
| `state.team` + `state.formation/captain/vice` | **FPL 官方实际快照**（auto_pick/主人手动后） | 账号真实状态 | ③「当前阵容」视图、Header 徽章 | `state.formation=442`、`state.captain=Gvardiol` |
| `state.points / rank / bank` | 官方赛季累计 | **总积分/总排名/银行** | ① Header、②、Sidebar B、D 核心数据 | `37 / 10331456 / 2.0` |
| `history[i].points/rank/overall_rank` | **该 GW 结算结果**（后端幂等回填，FPL finished 后自动补） | 该轮成绩 | ② 本轮成绩、⑤ Accordion、⑥ 趋势 | GW3: `37 / 9502808 / 10331456` |
| `state.suggested_squad` | 应用全部建议转会后的 **15 人完整快照** | 转会后阵容 | ③「转会后」视图 | 15 人含 Gakpo、C/Gvardiol 等 |
| `notes[]` / `decided_at` | AI 思考日志 / 决策时间 | 为什么 + 何时 | ④、⑤、Sidebar C | GW4 `decided_at=2026-09-09T11:12:32Z` |

| 字段 | 语义 | 展示 | 示例 |
|---|---|---|---|

### 6.6 建议性契约增量（实现阶段评估，非本阶段承诺）

## 8. 【交付物 6】后续视觉设计建议（Phase 3，暂不实施）

### 8.1 方向定性
- 参考 Animal Crossing 的**亲和力与轻松感**，但**不直接模仿游戏 UI**（不搬窗框、不仿按钮材质、不做像素风泛滥）。
- 定位：**现代网页设计 + 游戏化人格表达**——圆润、暖色、有"活着的感觉"，但保持信息可扫读的 Dashboard 骨架。
- 一句话校验标尺：**"像一本有人情味的球队手账，而不是一个游戏截图。"**

### 8.2 设计系统推进建议（可配 Open Design 目录选型）
1. 先定 **AI 人格名与头像**（🧅 小葱系列 SVG 头像，Phase 4 人格化叙事将复用）。
2. 进入视觉阶段时，从 Open Design 目录按"warm / playful / editorial-game"关键词扫描可用 DESIGN.md 作基底（需先 clone 内容库并让主人选型），再叠加下列自定义 token。
3. Token 草案（承接 v1.1 附录 A，微调为低饱和现代感）：
   - 背景：奶油白 `#FFF8EC`（浅色优先）；卡片 `#FFFFFF` + 暖灰描边
   - 主色：草地绿 `#7CB342`；辅助：天空蓝 `#A6D8FF` / 暖黄 `#FFD54F`（提示与高亮）
   - 语义色：红（下跌/转出）/ 绿（上涨/转入/正向）——遵循中文语境「转出→in」用色另议（足球语境无 A 股惯例约束，Phase 3 时按可读性定）
   - 文字：暖棕 `#3E2723` 主文字 / `#8D6E63` 次级；数字 `tabular-nums`
4. 字体：标题 Fredoka / Baloo 2 类圆体，正文系统圆体兜底；**避免全部圆体导致低信息密度**（标题圆、正文正）。
5. 组件-模块人格化映射（只做"气质"层，不改信息架构）：

| 模块 | 人格化表达（建议） |
|---|---|
| ① 本周动态 | 信件/任务卡隐喻：一页"它这周写给你的简报" |
| ② 本轮成绩 | 大数字卡 + 状态图章（「已结算」盖章感 /「进行中」虚线） |
| ③ 阵容 | 柔和草地色球场行；C/V 用木牌小徽章；新入球员卡加一枚「NEW」贴纸角标 |
| ④ 思考日志 | 便签/信纸质感首行缩进感（克制：不模拟真实纸张纹理过重） |
| ⑤ 历史 | 折叠条如"赛季日记目录"，展开即翻到那一周 |
| ⑥ 趋势 | 柔和面积渐变 + 圆点端点；排名轴上升即"变好"的方向隐喻（文案辅助，不只靠轴） |
| 头像/Header | 🧅 SVG 吉祥物，Header/Sidebar/移动摘要三处复用同一资产 |

6. 动效纪律：仅 micro 级（hover 浮起、展开过渡、Tab 淡切）；`prefers-reduced-motion` 全停；键盘可达（原生 details/tablist）。
7. 质量走查基线：桌面 1440 / 平板 768 / 移动 375；浅色优先、对比度 AA；截图走查沿用无头 Chrome file:// 方案。

### 8.3 "不做"清单（防越界）
- 不仿 ACNH 窗框/对话框/像素 UI；不做深色皮肤（浅色优先）；不动 IA/内容/UX 已定结构（视觉只改"皮"不改"骨"）。
